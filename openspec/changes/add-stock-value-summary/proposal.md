# Change: หน้าสรุปมูลค่าสต๊อก — ถ้าขายหมดจะได้เงินเท่าไหร่ (กรองตามล็อตนำเข้าได้)

## Why
หน้า `/stock-inventory` ตอบได้แค่ "มูลค่าสต๊อกตามต้นทุน" (คงเหลือ × ต้นทุนเฉลี่ย) และมัดรวมทุกครั้งที่รับเข้าเป็นก้อนเดียวต่อ SKU/สี/ไซส์ เจ้าของร้านจึงยังตอบไม่ได้ว่า "ของที่เหลืออยู่ถ้าขายหมดจะได้เงินเท่าไหร่" และ "ล็อตที่รับเข้ามาเมื่อไหร่ยังค้างอยู่เท่าไหร่" ซึ่งเป็นตัวเลขที่ใช้ตัดสินใจสั่งของ/จัดโปรล้างสต๊อก

## What Changes
- เพิ่ม `GET /api/stock?view=lots` — คืนสต๊อกราย **ล็อต** (1 แถว = 1 รายการที่รับเข้า `stock_in`) พร้อม `qty_sold` และ `remaining` ของล็อตนั้น
  - ยอดขายผูกกับล็อตผ่าน `sales_orders.stock_in_id` (บังคับกรอกตอนบันทึกขายอยู่แล้ว)
  - ยอดขายเก่าที่ไม่มี `stock_in_id` เกลี่ยแบบเข้าก่อน-ออกก่อน (FIFO) ภายใน SKU/สี/ไซส์เดียวกัน เพื่อให้ผลรวมตรงกับหน้า `สต๊อกคงเหลือ`
- เพิ่มหน้าใหม่ `/stock-value` ("สรุปมูลค่าสต๊อก") — เมนู `stock-value`
  - การ์ดสรุป: คงเหลือ (ชิ้น) · เงินทุนที่จมอยู่ · **ถ้าขายหมดจะได้เงิน** · กำไรคาดหวัง (+ % มาร์จิ้น)
  - ตัวกรองล็อตนำเข้า (เลือกได้หลายล็อต) + ค้นหา SKU/ชื่อ/สี/ไซส์ + สลับซ่อนรายการที่ขายหมดแล้ว
  - ตารางรายล็อต กดขยายดูรายสินค้าในล็อตได้ + แถวรวมท้ายตาราง
  - เตือนเมื่อมีของคงเหลือที่ยังไม่ได้ใส่ราคาขาย (ทำให้ยอด "ถ้าขายหมด" ต่ำกว่าจริง)
- เพิ่มเมนู `stock-value` ใน sidebar และในตัวเลือกสิทธิ์เมนูของบัญชีพนักงาน
- ไม่แก้ schema ฐานข้อมูล และไม่แตะการคำนวณเดิมของหน้า `/stock-inventory`

## Impact
- Affected specs: `stock-value` (ใหม่)
- Affected code:
  - `api/stock.js` — เพิ่ม `view=lots`
  - `src/lib/stock-api.ts` — `StockLotItem`, `getStockLots()`
  - `src/pages/StockValue.tsx` — หน้าใหม่
  - `src/components/layout/main-layout.tsx` — route `/stock-value`
  - `src/components/layout/sidebar.tsx` — เมนู "สรุปมูลค่าสต๊อก"
  - `src/components/employees/employee-accounts.tsx` — `MENU_OPTIONS`
- ไม่กระทบข้อมูลเดิม: อ่านอย่างเดียว ไม่มีการเขียนข้อมูล
